## 一、插件说明概述

### 1.1 插件做什么

这个插件做的只有一件事：把「翻到声明处读注释」变成「在当前这行就看到注释」。

```java
order.setCustomerName(name);              // customerName:客户姓名
order.setStatus(OrderStatus.UNPAID);      // 待支付 = UNPAID:待支付
submit(order.getOrderNo());               // 订单编号，全局唯一 = orderNo:订单编号
```

行尾的注释以 **inlay** 形式绘制，不进入文本流：行尾继续输入、后缀补全、回车换行都不受影响，注释始终留在原行。

### 1.2 功能一览

- **行尾中文注释**：字段、枚举常量、类常量、方法与构造器形参的注释贴在代码行尾。
- **悬停看完整注释**：在**引用处 / 调用点**（`obj.getPayNo()`、赋值、`OBJ.FIELD`）悬停，显示不截断的完整注释、来源（注解 / 文档注释 / 上方行注释 / 行尾注释）与所在行号，并可点「打开注释原文」直接跳过去；声明处交回平台原生文档。
- **Project 视图文件注释**：文件名后追加该文件的说明（由注解 / 文档注释 / 行注释聚合而来）。
- **注释覆盖率检查与报告**：类与 public 成员缺中文注释时告警，`Alt+Enter` 一键生成注释骨架；报告按目录 / 包名过滤扫描，导出 Markdown（总览 / 分语言 / 分包小计）。
- **数据库 Schema 反查**：字符串列名显示列注释与类型——来源可以是项目内 `.sql` 建表语句，也可以是 IDE Database 工具窗里已连好的数据源（零凭据、插件不另存连接）。PHP 查询构造器在行尾给提示，MyBatis Mapper 提供列名补全与悬停。
- **表名与取值补全（PHP）**：`Db::name / table('…')`、`model('…')`、`db('…')` 补全表名；`where('status', …)` 的取值位置补全模型常量 / enum case 与列注释里写明的取值。
- **展示与样式可调**：展示范围、大文件保护、标识符与注释各自的字体 / 字号 / 颜色、赋值符号、分隔符、注释截断长度。
- **中英双语界面**与**配置管理**（全部设置导出 / 导入 JSON、按设置组恢复默认）。

### 1.3 支持的语言与 IDE

| 环境 | 行尾提示 | Project 视图注释 | 设置子页 | 覆盖率检查 |
|---|---|---|---|---|
| IDEA（未装 PHP 插件） | Java ✅ / Kotlin ✅ / PHP ❌ | Java ✅ / Kotlin ✅ | 主 + Project 视图 + Java + Kotlin | Java + Kotlin |
| IDEA（装了 PHP 插件） | Java ✅ / Kotlin ✅ / PHP ✅ | Java ✅ / Kotlin ✅ / PHP ✅ | 全部（Go 除外） | Java + PHP + Kotlin |
| IDEA（装了 Go 插件） | 上述 + Go ✅ | 上述 + Go ✅ | 上述 + Go | 上述 + Go |
| PhpStorm | Kotlin ✅ / PHP ✅ / Java ❌ | Kotlin ✅ / PHP ✅ | 主 + Project 视图 + PHP + Kotlin | PHP + Kotlin |
| WebStorm 等其它 IDE | 都无 | 都无 | 主 + Project 视图 | 无 |

- Java、PHP、Go 都是**可选依赖**：IDE 缺哪个语言插件，就只启用其余语言，插件本身不受影响。
- **Kotlin** 是 IDEA / PhpStorm 的内置插件（`org.jetbrains.kotlin`），装了即启用；**Go** 插件需从 Marketplace 安装。
- 悬停文档（完整注释 + 来源）覆盖 Java / PHP / Kotlin / Go：各语言的检查与悬停分别注册，IDE 缺某个语言插件时该语言的能力不出现。

### 1.4 注释来源（命中即用）

| 语言 | 来源优先级 |
|---|---|
| Java | 注解值（Swagger 系 / 自定义）→ JavaDoc 摘要 → 相邻 / 行尾注释 |
| Kotlin | docblock 标签 → KDoc 摘要 → 相邻 / 行尾注释（标准库默认排除） |
| PHP | Attribute / docblock 标签（含 `self::CONST` 常量引用）→ PHPDoc 摘要 → 相邻 / 行尾注释 |
| Go | docblock 标签 → godoc → 行尾注释 |

调用点的实参说明取自 `@param`；形参本身没有说明时，回退为被调方法 / 类自身的注释。所有结果都可用「仅显示含中文的注释」过滤，并写入项目级缓存。

### 1.5 安装与首次启动

**安装**

1. `Settings / Preferences | Plugins`，在 Marketplace 搜索 `CN Comment Lens` 安装；离线安装走右上角 `⚙ | Install Plugin from Disk…`，选择发布包里的 zip。
2. 重启 IDE。

**首次启动**

| 时间点 | 现象 | 说明 |
|---|---|---|
| 刚打开项目 | 行尾暂无提示 | 首次需等索引构建完成（大项目几十秒到数分钟），索引完成后提示自动出现 |
| 每个插件版本首次打开项目 | 弹一次引导通知「CN Comment Lens 已就绪」 | 同版本不再出现，升级后会再弹一次；通知里可直接打开设置 |
| 打开完全没有中文注释的文件 | 编辑器顶部一条说明 | 解释「为什么行尾没有提示」，点「不再提示」永久关闭（全局开关，不是逐文件记忆） |
| 默认状态 | 覆盖率检查已开启 | 路径 `Settings \| Editor \| Inspections \| CN Comment Lens`，不需要可在此关闭 |
| 默认状态 | 数据库字段反查已开启 | 路径 `Settings \| Tools \| CN Comment Lens \| 数据库字段反查`；装完即用，打开项目即按已保存的筛选生效 |

**界面语言**：设置主页面第一项「插件语言」。可选「跟随 IDE 语言 / 中文 / English」，Apply 后新建或重开的界面立即生效，无需重启 IDE。

**设置树里的页面名称**只按 IDE 语言解析（平台约束）：想让菜单名变中文，请把 IDE 语言设为中文；插件的「插件语言」只影响页面内的文案。

### 1.6 已知限制

- 首次打开项目要等索引完成，行尾提示才会出现；Diff / 比较等虚拟编辑器里不显示提示。
- PHP：Attribute 常量引用只支持 `self::` 与本类短名，`use` 别名与跨类常量不支持。
- Kotlin：枚举条目与 object 声明不在提示与覆盖率口径内。
- Go：覆盖率只统计导出成员（结构体字段支持提示、暂不计入覆盖率）。
- Project 视图注释基于 Swing `JTree`，不支持逐节点改字体族与字号（颜色可改）。
- 反查：变量表名、子查询与闭包 `where` 会中断锚点回溯；join 只用于建立「别名 → 表」映射（不做 ON 条件与多表推断）；索引反映项目内 `.sql` 的当前内容，不是数据库实况；实时源只能看到已在 Database 工具窗展开（内省）的表 / 列；MyBatis 只解析同一语句块内的字面量表名（`<include>` 片段、动态标签与 `${}` 拼接的表名不猜）；表名补全在没输入前缀时最多返回 500 条候选。
- 数据库来源的注释只作为编辑时的兜底信息，**不计入**覆盖率口径（覆盖率见 3.4）。

## 三、插件功能说明

### 3.1 行尾中文注释

#### 3.1.1 显示形态

在代码行尾以 inlay 形式追加注释，格式为 `标识符:注释`；赋值语句上，形参注释与右侧实参字段名之间用赋值符号连接：

```java
order.setCustomerName(name);              // customerName:客户姓名
order.setStatus(OrderStatus.UNPAID);      // 待支付 = UNPAID:待支付
submit(order.getOrderNo());               // 订单编号，全局唯一 = orderNo:订单编号
```

- 标识符与注释之间固定用 `:`；同一行有多条提示时，默认用 ` | ` 分隔（设置里可改）。
- 赋值符号默认 `=`（设置里可改成 `←` 等；留空即恢复 `=`）。
- 关闭「始终显示标识符前缀」后只显示注释本身。
- inlay 不进入文本流：行尾继续输入、后缀补全、回车换行都不受影响，注释始终留在原行。

#### 3.1.2 支持哪些引用

| 语言 | 可显示注释的引用 |
|---|---|
| Java | 普通字段、getter / setter（反查其字段，含 Lombok `@Data` / `@Builder` / 构造器 / `@FieldNameConstants`）、枚举常量、`static final` 常量、方法调用处的形参（来自 `@param`） |
| Kotlin | 属性引用 `order.customerName`、函数调用处的形参（KDoc `@param`） |
| PHP | 类属性 `$this->amount` / `$obj->foo`、类常量与 enum case `self::X` / `Foo::BAR`、方法与构造器调用的形参（PHPDoc `@param`，含 `new Foo(...)`） |
| Go | 选择器引用 `s.Name` / `config.MaxSize`（结构体字段 / 常量 / 变量）、函数调用处显示被调函数自身的 godoc |

#### 3.1.3 注释来源与优先级（命中即用）

**Java**

| 优先级 | 来源 | 示例 |
|---|---|---|
| 1 | 注解值：Swagger 系内置注解（`@ApiModelProperty` / `@Schema`）+ 自定义注解 | `@ApiModelProperty("订单编号")` |
| 2 | JavaDoc 摘要 | `/** 订单编号，全局唯一 */` |
| 3 | 相邻注释：同行尾 `//`，或上方连续 `//` / 块注释 | `// 订单编号` |

**Kotlin**

| 优先级 | 来源 | 示例 |
|---|---|---|
| 1 | docblock 自定义标签（标签名需在设置里配置） | `@Comment("订单状态")` |
| 2 | KDoc 摘要 | `/** 订单总金额，单位：分 */` |
| 3 | 声明上方紧邻或同一行行尾的 `//` 行注释 | `// 下单时间` |

**PHP**

| 优先级 | 来源 | 示例 |
|---|---|---|
| 1 | PHP 8 Attribute / docblock 标签（标签名需配置），字符串（双 / 单引号）或 `self::CONST` 常量引用 | `#[Comment("订单状态")]`、`@Comment: 待支付`、`#[Comment(self::STATUS)]` |
| 2 | PHPDoc 摘要 | `/** 订单总金额，单位：分 */` |
| 3 | 声明上方紧邻或同一行行尾的 `//` / `#` 行注释 | `// 下单时间`、`$amount = 0; // 单位：分` |

**Go**

| 优先级 | 来源 | 示例 |
|---|---|---|
| 1 | docblock 自定义标签（标签名需配置） | `// @Comment: 待支付` |
| 2 | 声明上方紧邻的 godoc（`//` 行注释，取前 N 行） | `// 下单时间，Unix 秒` |
| 3 | 同一行行尾的 `//` 注释 | `maxSize = 100 // 单位：MB` |

**形参说明的两条细则**

- Java / Kotlin / PHP 的方法调用按 `@param` 逐实参显示说明；匹配时先按参数名，再按位置。
- 形参一条都没挂上说明时（缺 `@param` / 说明被「仅显示含中文」过滤掉），整条提示回退为**被调方法 / 类自身的注释**，并以方法名或类名为前缀。Go 无 `@param` 习惯，不做逐实参提示。

#### 3.1.4 展示范围与大文件保护

| 模式 | 行为 |
|---|---|
| 仅当前光标行 | 只渲染光标所在行 |
| 当前光标所在方法体内 | 渲染光标所在方法的行区间 |
| 整个文件（默认） | 全文件渲染；文件超过行数上限时自动关闭 |

- 设置项「文件行数上限」默认 5000（填 0 = 不限制），**仅「整个文件」展示时生效**。
- 超过上限：行尾提示自动关闭，编辑器顶部出现悬浮提示条，可一键「切换为当前方法」或「打开设置」。

#### 3.1.5 交互与开关

| 操作 | 效果 |
|---|---|
| 点击提示里的标识符段 | 跳转到声明位置（跨文件亦可）；DB 反查提示跳建表语句 |
| 悬停标识符段 | 小手光标 + 下划线 |
| 同一行提示较多 | 折叠为 `+N ▸`，点击展开完整列表 |

- 主设置页「启用行尾中文注释」；或 `Tools | CN Comment Lens | 行尾中文注释`；或编辑器右键菜单同名项。
- 快捷键 `Ctrl+Alt+Shift+K`（可在 `Settings | Keymap` 改键）。

### 3.2 悬停查看完整注释与注释来源

行尾提示受空间限制：默认截断 40 个汉字、只取前 1 行。要看**完整**注释，把鼠标停在**引用这个成员的位置**上，或在光标处按 Quick Documentation（Windows / Linux `Ctrl+Q`，macOS 默认 `F1`）。

**只在引用处 / 调用点生效，不在声明处**：声明处的注释就在上一行可见，而平台自带的悬停（JavaDoc / PHPDoc / KDoc / godoc）渲染更完整（标签、链接、语义高亮），所以那一格交回平台。插件补的是「注释看不见的地方」：

| 触发位置 | 弹窗内容 |
|---|---|
| 调用点 `payOrderEntity.getPayNo()` | 字段 `payNo` 的完整中文注释——访问器（getter / setter / builder setter）自身没写注释时，回到它背后的字段取值，与行尾提示同一条链 |
| 引用处 `order.setPayNo(x)` / `OBJ.payNo` / `Order.STATUS_PAID` | 对应字段 / 常量 / 枚举常量的完整中文注释，**不截断、不限行数** |
| 注解来源的成员引用 | `@TableField` / `@ApiModelProperty("…")` 里的整段说明（平台悬停是空白） |
| 上方行注释 / 行尾注释的成员引用 | 该注释（平台悬停是空白） |

弹窗里同时给出：

- **来源**类型（注解 / 文档注释 / 上方行注释 / 行尾注释）与所在行号——如「来源：文档注释 `/** 交易流水号（32位，含日期时间）*/`（OrderEntity.java:19）」，不点跳转就知道注释写在哪；
- 来源定位得到时提供「**打开注释原文**」链接：点击后编辑区定位到写注释的那一行（注解行 / 文档块 / 注释行都算），弹窗改为回显「已在编辑器定位到 `OrderEntity.java:19`」与该注释首行摘要——跳转的目的是把编辑器带到原文，不在弹窗里再复制一份内容。

两点说明：

- 只在成员确实有中文注释时才出内容；其余元素仍显示平台自带文档，不会被替换；
- 覆盖 **Java / PHP / Kotlin / Go** 四种语言（各语言能力按 IDE 是否装了对应插件出现，见 1.3）。

平台自带的悬停只认它认识的来源（Java 认 JavaDoc、PHP 认 PHPDoc、Kotlin 认 KDoc、Go 认 godoc），因此下面两类注释在悬停里原本是空白，现在能从**引用它们的地方**看到：

```java
@ApiModelProperty("订单编号，全局唯一，长度 32 位，由发号器生成")   // 注解来源：平台不认识 → 原本悬停为空
private String orderNo;

private String status; // 待支付/已支付/已退款（数据库存数字）        // 行尾注释来源：原本悬停为空
```

> 上面两行是**声明**：在声明上悬停看到的是平台原生文档。要体验本功能，请在引用它们的地方（`obj.getOrderNo()`、`orderNo = …`、`OBJ.orderNo`）悬停。

### 3.3 Project 视图文件注释

在 Project 视图的文件名后追加该文件的说明（灰色文字）。

**开启方式**：主设置页「在 Project 视图中显示文件注释」；或菜单 `Tools | CN Comment Lens | Project 视图文件注释`；或快捷键 `Ctrl+Alt+Shift+P`。

**取值优先级**

| 语言 | 取值顺序 |
|---|---|
| Java | Swagger `@Tag(name = "…")` → 自定义注解（按配置顺序）→ 文件头注释 → 字段级兜底（聚合字段的 doc / `//` 注释 / 注解值，最多 5 个，Lombok POJO 场景） |
| PHP | Project 视图子页配置的 docblock 标签 / Attribute → PHP 子页的自定义标签 / Attribute → 类 PHPDoc 摘要 → 类上方 `//` / `#` 行注释 → 文件头注释 |
| Kotlin | docblock 自定义标签 → KDoc 摘要 → 类上方紧邻 / 行尾 `//` 注释 → 文件头注释 |
| Go | docblock 自定义标签 → 前几个顶层声明（函数 / 方法 / 类型）的 godoc → 文件头注释（通常是包说明） |

**样式**（Project 视图子页）：颜色、最大汉字数、取前 N 行、跳过纯英文、文件注释自定义注解及其属性名。命名空间在此等价于包名，走 PHP 自己的黑白名单。

### 3.4 注释覆盖率检查

路径 `Settings | Editor | Inspections | CN Comment Lens | 缺少中文注释的公共成员`（默认开启，级别 WARNING，可调）。

| 语言 | 检查对象 | 不计入 |
|---|---|---|
| Java | 类（含接口 / 枚举）、public 方法与字段（含枚举常量） | 匿名类、private / protected 嵌套类、构造器、`@Override`、Object 通用方法（toString / equals 等）、getter / setter |
| Kotlin | 类 / 接口、public 函数与属性 | `override` 成员、internal / private、访问器、枚举条目与 object 声明 |
| PHP | 类（含接口 / trait）、public 方法 / 属性 / 常量 | 魔术方法（`__construct` 等）、访问器 |
| Go | 导出的函数 / 方法 / 类型（首字母大写，godoc 约定） | 结构体字段暂不统计（行尾提示支持） |

「已覆盖」的判定与行尾提示共用同一套注释来源链，任一条来源含中文即算覆盖。各语言的检查分别注册，IDE 缺少某个语言插件时，对应语言的检查不出现。

**快速修复**：光标停在被标记的成员上按 `Alt+Enter`：

- 「生成注释骨架」——在该成员上方插入含 `TODO 补充中文说明` 的 docblock（Java 用 JavaDoc、PHP 用 PHPDoc 语法）；成员需独占行首才可修复。
- 「为类及类内全部未覆盖成员生成注释骨架」——一次补齐整个类的缺口（类级与成员级告警上都提供），同一次修复的多处插入属一个命令，Undo 一步回退。

### 3.5 注释覆盖率报告

**入口**：`Tools | CN Comment Lens | 生成注释覆盖率报告`；或在 Project 视图右键某个目录 / 包 →「生成"目录名"的注释覆盖率报告」（对话框已预填该目录，仍可再加包名过滤）。

**扫描条件**（执行前必填）

| 条件 | 取值 |
|---|---|
| 范围 | 整个项目（默认）/ 指定目录（带浏览按钮与路径存在性校验） |
| 包名 / 命名空间过滤 | 英文分号分隔、支持 `*` 通配（如 `com.example.*;app.admin`），留空 = 全部 |

**报告内容**（Markdown，默认文件名 `cn-comment-coverage.md`，可另选保存位置，只含统计、不列具体文件与成员）

- 总览 / 分语言：文件数、成员数、已覆盖、缺失、覆盖率
- 分包小计：按包（Java / Kotlin 包、PHP 命名空间、Go 包路径）聚合，含合计行

**扫描口径**：只扫自己写的代码。Java / Kotlin / Go 取所有模块内容根（不含依赖库、JDK、标记排除的目录）；PHP 取项目内容根并排除 `vendor/`；Go 同时排除 `vendor/`。

**异常处理**：没有可用语言支持、或扫描到 0 个文件时，会给出明确结论而不是静默返回；报告写入失败（目录权限 / 磁盘空间等）给出**常驻**通知并带「打开报告目录」动作。

执行过程在后台任务里，可取消。

### 3.6 数据库 Schema 反查

反查是「`Settings | Tools | CN Comment Lens | 数据库字段反查`」这一页设置的公共能力，PHP 查询构造器与 MyBatis Mapper 共用同一份索引与开关。默认**开启**，装完即用——打开项目即按已保存的筛选生效并在后台探测一次活数据源，不需要先打开设置页点 Apply。

#### 3.6.1 它解决什么

ThinkPHP 查询构造器里的列名是字符串，IDE 无法从代码本身得到注释。开启反查后，这些字符串列名会显示来自**建表定义**的列注释：

```php
model('OrderAftersaleGoods')->where(['aftersale_id' => $ids])
    ->update(['return_amount' => $amount]);
// 📦 aftersale_id: 售后单ID | 📦 return_amount: 退货数量
```

前提与边界：

- 只处理 ThinkPHP 查询构造器，且只处理白名单方法（`where` 家族、`field` / `select` / `order` / `group` / `having`、`max` / `min` / `avg` / `sum` / `count`、`value` / `column` / `update` / `inc` / `dec`）；原生 SQL 方法（`whereRaw` 等）不参与。
- 三道闸门：必须找到唯一表锚点、列名形态在白名单内、列必须真实存在于索引。任一不满足就不提示。
- 注释来源有两处：项目内的 `.sql` 文件（**📦**）与 IDE 数据源（**🛢**），由「数据源策略」决定两者如何配合。
- 来源标记 📦 / 🛢 在行尾提示与悬停弹窗里同源：行尾用系统 emoji 字体绘制（macOS = Apple Color Emoji、Windows = Segoe UI Emoji），系统取不到该字体时退回 IDE 内置图标。图标含义见设置页「Schema 反查说明」。

#### 3.6.2 先分清四个概念：探测、快照、扫描、按库筛选

这是最容易混淆的部分。四者读取的数据、触发方式、结果出现的位置都不一样：

| 名称 | 读的是什么 | 怎么触发 | 结果在哪里看到 |
|---|---|---|---|
| **探测**（存活探测） | 只读 IDE 的数据源清单，判断「有没有可用数据源」；**不连库、不读表结构** | 自动：按「存活探测间隔」（默认 60 秒，最小 30 秒，0 = 关闭）；手动：「立即探测」 | 设置页状态行「上次探测：时间 · 可用 / 不可用（发现 N 个数据源）」；可用性发生变化时弹一次通知 |
| **快照** | 读 IDE 数据源模型里**已内省**的表 / 列 / 注释，在内存里存一份（不落盘） | 自动：按「实时快照刷新间隔」（默认 10 分钟，最小 5 分钟，0 = 关闭）；手动：「立即刷新」 | 状态行「刷新完成：N 张表 · 时间」；「数据表列表」里标 **🛢** 的表；编辑器里的 🛢 行尾提示 |
| **扫描**（.sql 索引） | 读项目内 `.sql` 文件里的 `CREATE TABLE` / `ALTER TABLE … COMMENT` / `COMMENT ON …` | 自动：启动即采用落盘缓存，`.sql` 变更自动跟进；手动：设置页「重新扫描 Schema」，或 PHP 查询构造器里 `Alt+Enter` →「重新扫描 .sql 索引」 | 状态行「扫描完成：N 张表 · 时间」+ 一条气球通知；「数据表列表」里标 **📦** 的表；编辑器里的 📦 行尾提示 |
| **按库筛选** | 限定实时数据源的读取范围 | 「只扫描这些库」+「选择库…」多选，Apply 即刻生效 | 「数据表列表」里的 🛢 表只剩选中库的表 |

一句话区分：**探测回答「数据源在不在」，快照回答「表结构是什么」，扫描回答「项目里的 .sql 说了什么」，按库筛选回答「只看哪几个库」。** 提示里的图标直接告诉你这条注释来自哪一侧——📦 来自 `.sql` 文件，🛢 来自实时数据源。

#### 3.6.3 探测

**用途**：确认 IDE 里是否已配置并连接数据源。它只读数据源清单，因此**不消耗数据库连接、不受权限影响**，也不会因为数据源很大而变慢。

**两种触发**

- 自动：按「存活探测间隔」轮询。默认 60 秒；最小 30 秒；填 0 表示关闭自动探测（手动按钮仍可用）。输入比下限小的非零值会自动吸附到下限。
- 手动：点「立即探测」。

**结果怎么看**

- 状态行显示「上次探测：时间 · 可用（发现 N 个数据源）」或「… · 不可用（发现 N 个数据源）」。
- 这条记录由手动探测与定时探测**共用**，所以关掉设置页、过一段时间再打开，看到的仍是最近一次探测的结果，不必再点一次。
- 数据源从「不可用」变为「可用」（或反向）时，会弹一次通知，例如「实时数据源已就绪：N 张表（数据源：X）」或「实时数据源不可用（未配置或未连接），已回退使用 .sql 索引」。

**注意**：探测**不包含表结构信息**。探测显示「可用」但表数是 0，说明数据源已连上但还没内省（见 3.6.4）。Database 插件没有可监听的「连接状态变化」事件，插件用定时探测代替，因此状态通知可能滞后一个探测间隔。

#### 3.6.4 快照

**用途**：把数据源模型里的表 / 列 / 注释一次性读进内存，供行尾提示与列名补全使用。

**范围限制**：只包含平台**已经内省过**的表 / 列——也就是你在 `Database` 工具窗里连接并**展开过**的数据源 / 库 / 表。若已配置数据源但模型里暂时没有表，状态行会提示「已配置数据源 [X]，但模型中暂无已内省的表（在 Database 工具窗连接 / 展开数据源后约 30 秒内自动生效）」。

**刷新方式**

- 自动：按「实时快照刷新间隔」在后台刷新，默认 10 分钟；最小 5 分钟；0 = 不自动刷新（只用手动刷新）。刷新不阻塞编辑。
- 手动：设置页「立即刷新」，或 `Alt+Enter` →「刷新实时数据库快照」。

**结束反馈（四态）**

| 状态 | 文案 |
|---|---|
| 进行中 | 正在后台刷新… |
| 完成 | 刷新完成：N 张表 · 时间 |
| 失败 / 取消 | 刷新未完成（模型不可用或已取消）——详情见插件日志 |
| 超时 | 表较多时刷新较慢，仍在后台进行——稍后回来查看 |

**快照不落盘**：只存在于内存中，IDE 重启后重新读取；因此不需要担心读到数据库里早已不存在的旧结构。

**点击行为**：行尾的 🛢 提示没有对应的 `.sql` 建表语句可跳，点击会打开插件**自动生成的只读 DDL 视图**（表头标注数据源与只读说明）。

#### 3.6.5 扫描（.sql 索引）

**索引来源**：项目内容根下 `.sql` 文件中的 `CREATE TABLE`、`ALTER TABLE … ADD / MODIFY / CHANGE COLUMN … COMMENT`（Navicat / DataGrip 导出的增量脚本常见）、PostgreSQL 的 `COMMENT ON COLUMN / TABLE`。`vendor/` 目录被排除；被注释掉的 SQL 语句不参与。

可用「DDL 路径模式」（分号分隔的相对项目根 glob，`*` 单层、`**` 跨目录，如 `db-script/**`）收窄扫描范围；留空 = 扫描项目内全部 `.sql`。项目里混有无关 SQL dump 时建议配置这一项。

**通常不需要手动扫描**：索引带修改戳落盘缓存，启动即用，`.sql` 变化会自动触发重建并刷新已打开的编辑器。

**这些情况需要点「重新扫描 Schema」**

- 刚修改了「DDL 路径模式」或「增量脚本目录」。
- 从版本库拉取了新的建表 / 增量脚本，而数据表列表数字与实际不符。
- 怀疑缓存陈旧（例如清理过缓存文件后想立刻重建）。
- `Alt+Enter` 里的「重新扫描 .sql 索引」适用于任何时候在编辑器里直接重建，不必切到设置页。

**反馈**

| 状态 | 文案 |
|---|---|
| 进行中 | 正在重新扫描 .sql 索引… |
| 完成 | 扫描完成：N 张表 · 时间（同时发一条气球通知，设置页已关闭也能看到结论） |
| 失败 | 扫描失败：原因——详情见插件日志 |

**数据表列表**：点「数据表列表」查看当前索引里的表（标题显示总数，支持按表名 / 表注释过滤），每张表用 **🛢**（实时源，已按选中库筛选）或 **📦**（项目内 `.sql` 文件，不受库筛选影响）标注来源。核对「某张表到底是从哪儿来的」时看这里。

**合并语义**：`CREATE` 先按路径字典序入索引（同名表按列先到先得），`ALTER` 再按仲裁序应用并**无条件覆盖** `CREATE` 的同列注释。多个增量文件对同一列给出不同注释时，按仲裁链取值：同文件语句序 → 「增量脚本时序正则」（可选）→ 「增量脚本目录」（可选）→ 路径字典序。冲突在悬停提示里以「⚠ 另一版本注释」标注，跳转跟随最终生效注释所在文件。

#### 3.6.6 只扫描这些数据源 / 这些库（两级筛选）

**两级筛选**：先按数据源、再按库。

- **「只扫描这些数据源」**：点「选择数据源…」多选 `Database` 工具窗里**已配置**的数据源（不触发内省）；留空 = 全部。未被选中的数据源**既不会被扫描**，其库也不会再出现在「选择库…」列表里——避免挑到「永远扫不出表」的库。
- **「只扫描这些库」**：粒度更细（格式「数据源#库名」），范围只含 Database 工具窗里**已展开（已内省）**的库。

两级都留空 = 「全部已配置数据源的全部已内省库」。任一级改动都会让旧快照立即失效并按新范围重拉，不会出现「改了筛选却还是旧范围数据」的中间态。

**MySQL 四个系统库不参与**：`information_schema` / `mysql` / `performance_schema` / `sys` 既不出现在「选择库…」候选里，快照也不读——它们对字段注释反查没有意义，混进来只会污染候选列表与数据表列表。

**作用范围**：只作用于**实时数据源**。`.sql` 文件侧不受这里影响，仍由「DDL 路径模式」控制——所以开启筛选后，数据表列表里仍可能出现 📦 的表，这是正常的。

**操作**

1. 点「选择库…」打开弹窗，列表里是 Database 模型里**已内省**的库，格式为「数据源#库名」。
2. 按住 `Ctrl` / `Shift` 多选；**双击某一行直接确认**；点「清空选择」或一个都不选 = 不限制（全部扫描）。「选择数据源…」的弹窗同理。
3. 确认后结果写入只读输入框（格式「数据源#库名」，英文分号分隔）。该框只经弹窗修改，避免手输格式出错。
4. 点 `Apply` 生效。

**限制**：库列表只包含 Database 工具窗里已展开（已内省）的库；选择之后新增的库需要重新勾选。

#### 3.6.7 数据源策略与回退

`Settings | Tools | CN Comment Lens | 数据库字段反查` 页的「数据源策略」：

| 策略 | 行为 | 适用场景 |
|---|---|---|
| 仅 .sql（默认） | 只使用项目内 `.sql` 索引，行为与不使用数据源时一致 | 离线环境、CI 服务器、团队统一以脚本为准 |
| 混合（数据库优先） | 数据库优先，`.sql` 兜底；**表级与列级都兜底** | 推荐。既反映数据库实况，又不会因数据源未连接而完全失去提示 |
| 仅数据库 | 完全使用 IDE 数据源：活库可用时**活库独占**，`.sql` 的表与注释都不参与；未连接 / 离线时整体回退 `.sql` 并在日志说明 | 数据库结构是唯一事实来源的项目 |

切换策略会立即在后台重新扫描并同步状态行与数据表列表，策略这一项因此不需要再点 Apply。策略选「仅 .sql」时，活库相关配置项（刷新 / 探测间隔、数据源与库筛选、两个「选择…」按钮）自动置灰——它们不起作用；「数据源策略」自身、立即探测 / 立即刷新、状态行与表前缀不置灰。

**零凭据**：三种策略都复用 `Database` 工具窗里已经配置好的连接，插件不保存、不索取账号密码，也不会主动发起新的连接。

**已连接活库却选了「仅 .sql」时会主动问一次**：`Database` 工具窗连上数据源后，若策略仍是「仅 .sql」（索引因此不含活库的表），插件在「立即探测」成功或点 `Apply` 时会弹一次确认框，可直接切到「仅活数据源」或「混合（活库优先）」——确认后立即重建索引并拉一次快照，因此数据表列表随即只剩所选范围的表（「只扫描这些库」已指定时仍按该筛选执行）。选择保持原样不会再反复询问（同一个设置页只在当次提示一次）。

#### 3.6.8 推荐上手顺序

1. 在 `Database` 工具窗里配置数据源并连接，**展开**目标库（让平台完成内省）。
2. 打开 `Settings | Tools | CN Comment Lens | 数据库字段反查`，确认总开关「数据库 Schema 反查」已勾选（**默认就是开启**；PHP 与 MyBatis 共用这一份设置，语言子页只留各自的注释来源项）。
3. 点「立即探测」，确认状态行显示「可用（发现 1 个数据源）」。
4. 若只想用某几个库：点「选择库…」多选后 `Apply`。
5. 点「立即刷新」，等状态行显示「刷新完成：N 张表 · 时间」；再点「数据表列表」核对表与来源标注。
6. 回到编辑器，在查询构造器的字符串列名上确认出现 🛢 提示。

若项目当前没有可用的数据源，走纯脚本路径：配置「DDL 路径模式」→ 点「重新扫描 Schema」→ 看「数据表列表」的 📦 表 → 回到编辑器确认 📦 提示。

#### 3.6.9 编辑器体验（PHP 查询构造器）

| 能力 | 说明 |
|---|---|
| 列名补全 | 在查询构造器的第一个字符串实参内补全，给出锚点表的**列名 + 注释 + 类型**候选；锚点不确定时不出候选 |
| 别名感知 | 链上 `alias('a')` / `join('t a', 'a.id=b.id')` / `leftJoin('db.t as a', …)` 会建立「别名 → 表」映射：`og.` 出主表列，ON 条件里的 `o.` 出对应 join 表的列；多列逗号续输按最后一段过滤 |
| 悬停 | 📦 / 🛢 提示悬停显示「表名 · 表注释 · 列类型」（行尾空间有限，只显示列注释，气泡里给完整注释） |
| 点击跳转 | 📦 提示跳转到建表语句对应行；🛢 提示打开自动生成的只读 DDL 视图 |
| 展开 | 同一行内容较长时折叠为 `+N ▸`，点击弹出「全部字段注释」，条目可点击跳转建表语句 |
| 一键修复 | 光标在查询构造器字符串里按 `Alt+Enter`，可执行：打开 Schema 反查设置 / 刷新实时数据库快照 / 重新扫描 .sql 索引 |
| 表名补全 | `Db::name('` / `Db::table('` / `model('` / `M('` / `db('` 的字符串实参内补全索引里的**表名**：类型位显示来源标记（🛢 实时源 / 📦 .sql），尾部显示表注释；`db('库:表')` 的冒号语法按冒号后的表名匹配 |
| 取值补全 | `where('status', <caret>)` 这类「列名 + 取值」位置：给出模型类中**与列名相关**的常量 / enum case（如 `Order::STATUS_PAID`，说明取常量自身的中文注释），以及列注释里写明的取值（注释写 `1:待支付` → 候选 `1`）。只有链上能解析到模型类时才出常量候选（`Order::where(…)`；`model('Order')` 这类只有表名的锚点不猜类） |

**表锚点**（沿链向根部回溯，取最近的一个）：`model('X')` / `M('X')`（类短名转蛇形）、`db('x')`（`db('库:表')` 取冒号后的表名）、`Db::name('x')`、`Db::table('x')`（全名，不拼前缀）、模型静态调用 `X::where()`（读 `$name` / `$table` 属性，回退类名蛇形化）、`$this->model->where(...)`（解析 model 属性默认值里的 `new \app\...\Xxx`）。

**表前缀**：在「数据库字段反查」页统一配置（PHP 与 MyBatis 共用，分号分隔多个）。填写的值会在用 `Db::name()` / 模型类名推断出的短表名查索引前逐个拼接；全部未命中时回退查裸表名，因此 DDL 里没写前缀也能命中。它只影响反查与补全的匹配，不参与索引构建，也不筛选数据表列表。

**表名补全与短名**：补全表名时，写**短名**（`db('ad')`）会按去掉表前缀后的名字匹配，并插入短名（`addons`）——运行时由框架自己拼前缀，插入全名会变成 `hx_addons` 再拼一次；写全名（`db('hx_ad')`）则按全名匹配、插入全名。

**与覆盖率无关**：反查只是编辑时的兜底信息，数据库来源的注释**不计入**「已覆盖」，覆盖率检查与报告口径不受其影响。

#### 3.6.10 MyBatis Mapper 反查

同一份索引与总开关也服务 MyBatis：在 Mapper XML 的语句里写 `t1.` 就会给出该表字段的**列名 + 类型 + 中文注释**。

| 能力 | 说明 |
|---|---|
| 列名补全 | 光标前是「别名.」（如 `t1.`）时，候选来自该别名指向的表：**候选前是 Database 的列图标**（未装 Database 插件时无图标），尾部是中文注释、类型位是列类型；候选**覆盖** IDE 自带的那份（平台给的是别名分组且没有中文注释） |
| 悬停 | 在 `t1.pay_no` 这类引用上悬停，**按数据源分行**：每个真的提供该列的来源一行「图标 · 字段中文注释 · 字段类型」，末行是表英文名（表注释与它合并；字段名不重复显示——用户就是悬停在它上面）。`📦` = 项目内 .sql，`🛢` = 实时数据库：只有活库真的提供了该列才出 🛢 行，只有 .sql 里存在该列才出 📦 行——两处注释不一致时正好各看一行。两个来源都定位不到时退回无图标一行，**悬停绝不空白**。长注释自动折行；同一列被多个增量文件赋了不同注释时，末尾附上被淘汰的那一版 |
| 来源行点击 | **有多个来源时**，点 🛢 行的中文注释跳到活库只读 DDL 视图、点 📦 行跳到 .sql 的来源行；**只有一个来源时注释是纯文本**（没有第二个去处）。点击后弹窗自动关闭，编辑器直接落到目标行 |
| 悬停链接（字段本身） | 编辑器里把鼠标移到 `t1.pay_no` 上：该引用加**下划线**、光标变**手型**（与行尾提示的标识符段同一套交互）；**无修饰键单击**即跳到该列的定义处——`.sql` 的**列级**来源行（ALTER 改过的注释落在增量文件里）或**只读 DDL 视图**的该列行。`Ctrl` / `Cmd`+单击仍是平台原生的 Go-to。只有「该列在 .sql 或活库里查得到」时才出现下划线，不会给出点不动的死链 |
| 点击跳转 | `📦` 跳到该列所在的建表 / ALTER 行（列级来源优先，改过注释的列会落到增量文件）；`🛢` 打开自动生成的只读 DDL 视图并定位到该列 |
| 表名解析 | 只解析**同一语句块内**的字面量表名：`from` / `join` / `update` / `insert into`，以及 `from` 列表里的逗号分隔表；别名与表名都按小写比对（`t1.id` 与 `pay_receipt.id` 都能命中） |
| 不解析的情形 | `<include refid>` 片段、动态标签（`<if>` / `<foreach>`）里的表名、`${}` 拼接的表名——这些解析不出别名到表的映射，因此不出候选也不接管悬停（宁缺勿错） |

**索引来源（重要）**：Mapper 反查与 PHP 查询构造器**共用同一份索引**——想用**实时数据库源**（🛢），请把「数据源策略」设为「仅数据库」或「混合（数据库优先）」，Apply 后点一次「立即刷新」。默认的「仅 .sql」策略下索引**不含活库数据**：项目内若没有 .sql 建表文件，表数就是 0（这时补全与悬停都不会出结果，设置页会在状态行给出提示，点「数据表列表」也会说明原因）。

**开关只有一个**：「数据库字段反查」页的总开关（默认开启），PHP 与 MyBatis 一起受它控制。MyBatis 没有子开关，表前缀也是该页的公共项（PHP 与 MyBatis 共用一份）——同一个功能放两处开关只会让人分不清哪一份生效。

**表前缀**：Mapper 里写的短表名会先拼「表前缀」再查索引，都未命中时回退查裸表名（DDL 里没写前缀也能命中），与 PHP 侧同一策略。

**与行尾提示无关**：Mapper 反查只提供补全与悬停，不在 Mapper 里画行尾提示。

## 五、常见问题

### 5.1 行尾提示

**行尾提示一直不出现**
先确认已索引完成（大项目首次较慢）；再确认「启用行尾中文注释」为开、展示范围覆盖了当前光标位置、文件未超行数上限；若该文件本身没有任何中文注释，编辑器顶部会给出说明——这是预期行为。

**为什么某些行没有提示**
行尾提示的内容来自中文注释。字段 / 常量 / 形参没有任何中文注释来源时不会提示；开启了「仅显示含中文的注释」时，纯英文注释会被跳过；数据库列注释不算「已覆盖」，但会作为提示显示。

**Diff / 比较视图里没有提示**
虚拟编辑器（比较、历史对比）不渲染行尾提示。

**改了设置为什么有几个文件没立刻变**
设置生效依赖「清缓存 + 守护进程重跑」，通常几百毫秒内完成，大文件可能稍久。

**改了声明处的注释，别处的行尾提示没跟着变？**
调用点显示的文本取自声明处（字段 / 常量 / 方法的注释），因此声明处注释一改，引用它的文件需要重画。插件会在声明处变更停顿后自动重画**当前打开**的引用方文件，通常半秒内可见；目标文件若没有打开，打开时直接就是新注释。同一文件内的修改本来就是即时更新。

### 5.2 悬停文档

**悬停看不到「完整注释 / 来源」**
覆盖 Java / PHP / Kotlin / Go 的字段 / 常量 / 方法 / 类，以及**调用点**（`obj.getPayNo()` 这类，靠引用解析）。
若悬停无内容，先确认该成员确实有中文注释；再确认是在**引用处**而非声明处悬停（声明处交回平台原生文档）。Java / PHP 侧还会写一行 debug 日志，排障时打开插件日志的 DEBUG（见 5.5），悬停时会出现一行「悬停文档（Java/PHP）：… member=…, hit=…」——`member=null` 说明该位置没被识别为成员（例如在方法体中间或局部变量上悬停，属预期行为）。

### 5.3 Project 视图与覆盖率

**Project 视图注释的字体 / 字号改不动**
Project 视图基于 Swing `JTree`，不支持逐节点改字体族与字号；颜色设置已生效，字体 / 字号项暂只存储。

**PHP enum case 与常量引用**
enum case 按普通常量处理；Attribute 常量引用只解析 `self::` 与本类短名，`use` 别名与跨类常量不支持。

**Kotlin 的枚举条目 / object 声明**
暂不在行尾提示与覆盖率口径内。

**Go 的覆盖率为什么不统计结构体字段**
覆盖率口径遵循 godoc 约定，只查导出成员；结构体字段的行尾提示支持，但不计入覆盖率统计。

### 5.4 数据库反查

| 现象 | 原因 | 处置 |
|---|---|---|
| 完全没有 📦 / 🛢 提示 | 反查开关未开；或链上锚点未识别（变量表名 `Db::name($table)`、子查询 / 闭包 `where` 会中断回溯）；或列不在索引里；或该注释不含中文且开了「仅显示含中文」 | 先确认开关；再按 `Alt+Enter` 用一键修复项排查（打开设置 / 刷新快照 / 重扫 `.sql`） |
| 数据表列表里出现非选中库的表 | 若这些表带 📦，来自项目 `.sql` 文件，不受库筛选影响（正常）；若带 🛢，说明是改选前的旧快照 | 改选即作废旧快照并按新范围重拉；仍不符时点「立即刷新」再看 |
| 状态行一直停在「正在后台刷新…」 | 上一轮任务被取消，或表很多仍在进行 | 会给出完成 / 失败 / 超时结论；若长时间无结论，看插件日志确认原因 |
| 「立即探测」显示可用，但没有提示 | 探测只判断数据源在不在，不含表结构 | 用「立即刷新」确认快照表数；表数为 0 时先到 Database 工具窗展开数据源 |
| 可用性通知来得晚 | Database 插件没有连接状态事件，靠定时探测 | 调小「存活探测间隔」（最小 30 秒），或点「立即探测」 |
| 「选择库…」列表为空 | 数据源尚未连接，或库尚未展开；也可能只有系统库 | 先在 Database 工具窗连接并展开库，再重开弹窗 |
| 选了「仅数据库」却没有 🛢 提示 | 活库不可用，已整体回退 `.sql` | 点「立即探测」确认状态；日志里会说明回退原因 |
| 提示里的类型 / 表名不对 | `.sql` 索引停留在旧内容，或该列被多个增量文件以不同注释定义 | 点「重新扫描 Schema」；把鼠标停在提示上看冲突标注 |
| `.sql` 侧想收窄范围 | 「只扫描这些库」只管实时源 | 改用「DDL 路径模式」限定 `.sql` 扫描范围 |
| MyBatis 里 `别名.` 不出候选 | 表名不在同一语句块内的 `from` / `join` / `update` / `insert into` 里；或该表不在索引中；或策略是「仅 .sql」而项目内没有建表脚本 | 确认表名写法与索引内容（看「数据表列表」），必要时切策略并「立即刷新」 |

### 5.5 日志与反馈

遇到「提示缺失」「刷新失败」「扫描失败」等问题时，先看插件专用日志：

- 位置：IDE 日志目录下的 `cn-comment-lens.0.log`，可用 `Help | Show Log in Finder / Explorer` 打开同目录。
- 规则：单文件 10MB，保留 5 份滚动；与 `idea.log` 分离，不影响 IDE 自身日志。
- 内容：数据源可用性变化与回退说明、快照刷新与 `.sql` 扫描的失败原因、反查与补全的异常等。
- 日志级别：诊断日志不开常驻 info（避免刷日志）；排障时在 `Help | Diagnostic Tools | Debug Log Settings` 里加入 `com.jzt.international` 打开 debug。

反馈问题时，附上日志片段、插件版本（`Settings | Plugins | Installed` 里可看）、IDE 与版本、以及复现步骤，定位会快很多。
